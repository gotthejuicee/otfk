# План поэтапного улучшения UX админки

> Цель: управление сайтом должно быть простым и понятным для сотрудника колледжа без технических знаний.
> Каждый этап самодостаточен и деплоится отдельно. Правила проекта — [CLAUDE.md](CLAUDE.md), справочник — [ARCHITECTURE.md](ARCHITECTURE.md).
> Обновление визуального стиля админки — отдельная задача, здесь не рассматривается.

## Этап 0 — сделано (эта правка)

- Кнопка «Переглянути на сайті» во всех ресурсах: в шапке Edit-страниц и в строках таблиц (хелпер `app/Filament/Support/ViewOnSite.php`). Для списочных разделов (события, FAQ, видео, баннеры, статистика, квиз, меню, быстрые ссылки, звонки) — кнопка на List-странице ведёт на соответствующий раздел сайта.
- Превью черновиков: неопубликованные страницы и новости открываются залогиненным админом с жёлтой плашкой «Чернетка» (`components/draft-notice.blade.php`); гостям по-прежнему 404, просмотры черновиков не считаются. Тест: `tests/Feature/DraftPreviewTest.php`.
- Превью несохранённой формы (бывший Этап 4, сделан досрочно): кнопка «Превʼю» на формах создания/редактирования страниц и новостей (`app/Filament/Support/PreviewFormAction.php`) — состояние формы кладётся слепком в кэш (`app/Support/AdminPreview.php`, TTL 10 мин), `/admin-preview/{token}` рендерит настоящий публичный шаблон без записи в БД, с плашкой «Попередній перегляд». Файлы (обложка) в слепок не входят — показывается сохранённое значение. Тест: `tests/Feature/FormPreviewTest.php`.

## Этап 1 — сделано (быстрые победы, мелкие правки ресурсов)

Реализовано целиком; смоук-тест рендера всех List-страниц и контракта «у новостей нет тумблера в таблице» — `tests/Feature/AdminTablesTest.php`. По п. 2 для новостей выбран вариант «переключение только в форме» (без тумблера с подтверждением). Исходные пункты:

1. **Порядок перетаскиванием.** `->reorderable('sort_order')` в таблицах MenuItem, QuickLink, Faq, StatItem, DocumentCategory, Specialty, Department, Staff — вместо ручного числового поля «Порядок» (поле оставить, но убрать из форм на второй план). Для меню — `->defaultGroup('parent.label')`, чтобы перетаскивание шло внутри своего уровня.
2. **Инлайн-тумблеры публикации.** `ToggleColumn` для `is_published` / `is_visible` в таблицах (страницы, документы, галереи, персонал, меню). **Осторожно с новостями:** `NewsObserver::saved()` шлёт автопост в Telegram при переходе новости в «живое» состояние — тумблер в таблице делает это доступным в один клик. Для новостей оставить переключение только в форме, либо добавить `->requiresConfirmation()` с текстом про Telegram.
3. **Превью URL под полем slug.** Во всех формах со slug показывать итоговый адрес (`->prefix(url('/'))` или helperText с живым URL) — сейчас админ не видит, какой адрес получится.
4. **Фильтры таблиц.** Страницы: фильтр по разделу (parent) и «только черновики»; новости: по категории и году; документы: по категории; персонал: по подразделению и категории.
5. **Понятные пустые состояния.** `->emptyStateHeading()/->emptyStateDescription()` с подсказкой «что это и зачем» для каждого ресурса (сейчас голое «No Сторінки»).

Примечания по реализации: пустые состояния добавлены во все контентные ресурсы (включая события, видео, баннеры, квиз, категории, программы); поле «Порядок» оставлено в формах с подсказкой про перетаскивание; фильтр «черновики» добавлен также новостям.

## Этап 2 — сделано (человеческие «Налаштування»)

Реализовано целиком: четыре страницы-формы (общая база `app/Filament/Support/SettingsFormPage.php`) вместо работы с сырым key-value; `SettingResource` переименован в «Розширені налаштування» и опущен в низ группы как аварийный доступ (из навигации не скрыт). Кнопка «Надіслати тестове повідомлення» шлёт тест с незохранённых значений формы (`TelegramPoster::sendTest()`); маскировка токена закрывает экранную часть PoC-only #13 (в БД токен по-прежнему плейнтекст — строка в ARCHITECTURE.md обновлена). Затемнение баннеров оставлено только в «Банери». Тесты: `tests/Feature/SettingsPagesTest.php`. Исходные пункты:

1. Страница **«Контакти та соцмережі»**: contact_address / contact_phone / contact_email / work_hours / map_embed / social_facebook / social_instagram / social_youtube — обычные подписанные поля, сохранение через `Setting::updateOrCreate` + `Cache::forget('settings.map')`.
2. Страница **«Оголошення»**: announcement_text / announcement_type (Select с человеческими названиями цветов) / announcement_url + предпросмотр полосы.
3. Страница **«Telegram»**: telegram_autopost (Toggle) / telegram_bot_token (поле-пароль, маскировать — заодно закрывает PoC-only #13) / telegram_channel + кнопка «Надіслати тестове повідомлення».
4. Страница **«Підвал і вигляд»**: footer_about / site_version_label / site_version_color / banner_overlay_opacity (последнее уже дублируется в «Банери» — оставить одно место).
5. `SettingResource` переименовать в «Розширені налаштування» и спрятать вниз навигации (или за `shouldRegisterNavigation` = только по прямой ссылке) — оставить как аварийный доступ.

## Этап 3 — сделано (удобство редактирования контента)

Реализовано целиком, тест этапа — `tests/Feature/AdminEditingToolsTest.php`. Исходные пункты:

1. **Загрузка изображений в текст** — у `RichEditor` страниц и новостей включены attachments (диск `public`, каталоги `pages`/`news`) + подсказка под полем.
2. **Действие «Дублювати»** в таблицах страниц и новостей: копия-черновик «… (копія)» со слагом `-kopiya[-N]` (`app/Support/UniqueSlug.php`), у новостей обнуляются views/likes/`telegram_posted_at` (автопост не срабатывает — копия не опубликована); после дублирования — редирект в редактирование копии.
3. **Проверка битых внутренних ссылок** — движок `app/Support/LinkChecker.php` (несуществующие страницы/разделы, черновики, отсутствующие файлы `storage`, ссылки на старый otfk.od.ua; внешние не проверяются), интерфейсы: `php artisan otfk:check-links` (exit 1 при находках) и страница админки «Биті посилання» (кэш 10 мин + кнопка «Перевірити заново»).
4. **Виджет «Чернетки»** на дашборде (`app/Filament/Widgets/Drafts.php`): неопубликованные страницы/новости одним списком, «Редагувати» + «Перегляд» (превью черновика на сайте); при отсутствии черновиков виджет скрыт.

## Этап 4 — доводка превью несохранённых изменений

Базовая версия сделана в Этапе 0 (кнопка «Превʼю» → новая вкладка). Возможные улучшения:

1. Показ свежезагруженной (ещё не сохранённой) обложки в превью — сейчас файлы в слепок не попадают.
2. Превью в модалке-iframe рядом с формой (side-by-side) вместо новой вкладки.
3. Кнопка «Превʼю» для специальностей/подразделений/персонала, если редакция попросит.

Низкий приоритет: текущей версии для рабочего процесса достаточно.

## Этап 5 — сопровождение

1. Обновить ручной мануал `docs/posibnyk-administratora.html` под всё вышесделанное (он уже дрейфует — Gotcha 22).
2. Пройтись по helperText всех форм: каждое поле должно отвечать «что это и где на сайте видно».
3. После появления ролей (PoC-only #2) — скрыть «Адміністратори» и «Розширені налаштування» от не-суперадминов.

## Порядок и зависимости

Этапы 1–4 независимы друг от друга, можно в любом порядке (4 — низкий приоритет); Этап 5 — финальный проход. После каждого этапа: `php artisan test`, обновление ARCHITECTURE.md (+ `node DocsHtml/generate.mjs`).

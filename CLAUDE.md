# CLAUDE.md — рабочие правила проекта otfk

## Порядок чтения для новой задачи

1. Этот файл (CLAUDE.md).
2. [ARCHITECTURE.md](ARCHITECTURE.md) — полный справочник: карта маршрутов, схема БД, CI/деплой, **Gotchas** и **PoC-only**. Перед правкой любого маршрута, миграции или workflow — обязателен.
3. Затем — код. При конфликте доков и кода **побеждает код** (и это повод исправить доки).

## TL;DR проекта

Сайт Одесского технического фахового колледжа ОНТУ — **Laravel 12 + Filament 3** (не «чистый PHP»), Blade + Tailwind v4 + Alpine 3, Vite 7. Прод: MySQL на shared-хостинге ukraine.com.ua — **без Node и без queue-воркера**. Dev: SQLite, `php artisan serve --port=8002` (`.claude/launch.json`), тесты `composer test`. Статус — **PoC**: ролей нет, много демо-контента; всё временное учтено в разделе PoC-only в ARCHITECTURE.md.

## Конвенции кода (фактические, из существующего кода)

- Комментарии и docblocks — **на украинском**; UI-строки захардкожены в Blade по-украински. Локаль приложения — `uk` (`APP_LOCALE=uk` во всех env, fallback в `config/app.php` тоже `uk`): даты через `translatedFormat`, хром Filament и `lang/uk` (validation, pagination) — украинские; не возвращать `en`.
- URL-слаги — транслит украинского: `/novyny`, `/spetsialnosti`, `/rozklad-dzvinkiv`. Новые роуты именовать так же.
- Отступы 4 пробела (2 для YAML), LF — `.editorconfig`. Форматтер `laravel/pint` установлен, но в CI не гоняется.
- Контроллеры публичной части тонкие; списки — через модельные scopes (`published`, `ordered`, `active`, `visible`). Автослаг — в `booted()`/`saving` моделей.
- Админка — только Filament Resources (auto-discovery), ручных админ-роутов не писать.
- Фоновое — только `dispatch(...)->afterResponse()`. Кэш точечный: `Setting::map()`, `MenuItem::navigation()`, `BellPeriod::active()` по 600с, со сбросом в `booted()`.
- Контент-фикстуры — идемпотентные data-миграции (`firstOrCreate`, guard-проверки, `down()` не удаляет контент).
- Тесты — PHPUnit Feature-тесты, фиксируют поведенческие контракты; на каждую фичу — тест в `tests/Feature/`.

## Жёсткие правила «не трогать»

- **Не переводить джобы на `ShouldQueue`** — на хостинге нет воркера; `afterResponse()` — осознанное решение (DEPLOY.md).
- **Не возвращать тёмную тему / theme-toggle** — light-only закреплён тестом `FrontendPolishTest::test_site_is_light_only_without_theme_toggle`.
- **Не менять `'timezone' => 'UTC'`** в `config/app.php` без сквозной ревизии: даты хранятся как киевское wall-clock и вручную шифтуются в 5 местах (см. Gotcha «Таймзона»).
- **Catch-all `/{page:slug}`** остаётся последним в `routes/web.php`; новый top-level путь → добавить в регексп исключений в той же правке.
- **Не запускать `db:seed` / `SiteSeeder` на окружении с реальным контентом** — сидер деструктивен (delete меню, персонала, видео, баннеров).
- **`public/build/` в git не коммитить** (он в `.gitignore`) — прод-бандл собирает деплой-workflow `deploy.yml` и заливает rsync-ом. Локально для проверки — `npm run build` или `npm run dev`.
- **Деплой:** push в `master` = автодеплой на прод (`.github/workflows/deploy.yml`). Не пушить в `master` без явной просьбы пользователя (правило «не коммитить/не пушить» теперь ещё и деплоит).
- **`ARCHITECTURE.html` и прочие HTML-твины руками не редактировать** — только `node DocsHtml/generate.mjs`.
- Слаг `istoriya` (drop cap) и страница `abituriyentu` (7 хардкод-ссылок) — не переименовывать без правки шаблонов и тестов.
- `NewsObserver` подключён атрибутом `#[ObservedBy]` на модели `News` — помни про Telegram-сайд-эффект при любых правках новостей.

## PoC-элементы

Проект — PoC: часть путей/кнопок/данных в прод не пойдёт. Правила:
- Добавляешь новый временный путь, кнопку, заглушку, хардкод — **сразу** вноси строку в таблицу «PoC-only» в ARCHITECTURE.md (в той же правке).
- Удаляешь/финализируешь PoC-элемент — убери его строку оттуда же.
- Полный текущий список — ARCHITECTURE.md → «PoC-only».

## Keep docs in sync (обязательно)

- **(A)** После любого изменения кода проверь диф на предмет устаревания ARCHITECTURE.md / CLAUDE.md; если устарело — обнови **в том же изменении**. Обязательные триггеры: новый/изменённый маршрут, изменение схемы БД или настроек (`settings`-ключи), новый/изменённый workflow или деплой-шаг, новые PoC-элементы.
- **(B)** Нашёл во время исследования, что доки врут или молчат о важном — исправь проактивно, но только проверенное по коду. Правь существующий текст по месту, не дописывай вторую версию рядом.
- **(C)** Механически всегда: тронул любой `ARCHITECTURE.md` → в том же изменении прогони `node DocsHtml/generate.mjs` и включи обновлённый `.html` в правку.
- Удалять устаревшее — разрешено и ожидается. При конфликте доков и кода побеждает код.
